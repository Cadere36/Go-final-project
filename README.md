# Итоговый проект курса «Go-разработчик с нуля»

Планировщик задач (TODO-лист): веб-сервер на Go с REST API и готовым фронтендом. Задачи хранятся в SQLite. Задачи можно добавлять, редактировать, удалять и отмечать выполненными. У задачи может быть правило повторения. Выполненная повторяющаяся задача переносится на следующую дату, а обычная удаляется. Есть поиск по тексту и по дате.

## Задачи со звёздочкой

Выполнены все задания повышенной сложности.

1. **Порт из `TODO_PORT`.** Порт читается через `os.Getenv("TODO_PORT")` в `internal/server`. Переменную можно задать в файле `.env`, его читает `godotenv.Load()` (github.com/joho/godotenv). Если переменная не задана, используется порт `7540`.
2. **Путь к базе из `TODO_DBFILE`.** Схема та же, по умолчанию используется `scheduler.db`. Путь передаётся в `db.Init`, таблица и индекс создаются через `CREATE ... IF NOT EXISTS`.
3. **Правила повторения `w` и `m`** (`internal/scheduler`):
    - правило разбирается в массивы `[8]bool` для дней недели, `[32]bool` для дней месяца и `[13]bool` для месяцев; последний (`-1`) и предпоследний (`-2`) день месяца хранятся отдельными флагами `last` и `preLast`;
    - затем идёт перебор по одному дню от `dstart`, пока дата не станет больше `now` и не совпадёт с правилом;
    - день считается последним, если завтра уже другой месяц, и предпоследним, если завтра тот же месяц, а послезавтра уже другой;
    - цикл ограничен 3650 итерациями, чтобы сервер не зависал на невозможных правилах вроде `m 31 2`.
4. **Поиск** (`internal/api/tasks.go` и `internal/db`):

go

```go
   if search == "" {
       tasks, err = db.Tasks(tasksLimit) // обычный список
   } else if t, perr := time.Parse("02.01.2006", search); perr == nil {
       tasks, err = db.TasksByDate(t.Format(scheduler.DateFormat), tasksLimit) // поиск по дате
   } else {
       tasks, err = db.TasksBySearch(search, tasksLimit) // поиск по заголовку и комментарию, LIKE ?
   }
```

Символы `%` добавляются в аргумент запроса, а не в сам SQL. Это защищает от SQL-инъекций.

**Ограничение:** для кириллицы поиск чувствителен к регистру из-за особенности `LIKE` в SQLite. Поэтому «Бассейн» и «бассейн» дадут разные результаты. 
5. **Аутентификация** (`internal/auth`, `internal/api/signHandler.go`):

- `POST /api/signin` сверяет пароль с `TODO_PASSWORD` и выдаёт JWT (HS256). Внутри токена лежат sha256-хэш пароля и срок жизни 8 часов;
- `authMiddleware` защищает `/api/task`, `/api/tasks` и `/api/task/done`. Он берёт куку `token` и проверяет подпись, срок жизни и совпадение хэша с текущим паролем, поэтому при смене пароля старые токены перестают работать. При ошибке возвращается `401`, и фронтенд переводит пользователя на `/login.html`;
- если переменная окружения `TODO_PASSWORD` не задана, аутентификация выключена.

6. **Docker.** Сборка многоэтапная: компиляция на `golang:1.26`, запуск на `ubuntu:latest`. Бинарник собирается статическим с `CGO_ENABLED=0`, это возможно благодаря драйверу `modernc.org/sqlite`, написанному на чистом Go. База лежит в папке `/data`, которая монтируется томом с хоста, поэтому данные переживают пересоздание контейнера. Пароль в образ не зашит, он передаётся через `-e` при запуске.

## Запуск локально

Запускать нужно из **корня проекта**, иначе сервер не найдёт папку `web/` и файл `.env`:

bash

```bash
go run .
```

После запуска планировщик доступен по адресу [http://localhost:7540](http://localhost:7540) (или на порту из `TODO_PORT`).

Все переменные необязательные. Пример `.env` в корне проекта:

env

```env
# порт веб-сервера (по умолчанию 7540)
TODO_PORT=7540
# путь к файлу базы (по умолчанию scheduler.db)
TODO_DBFILE=scheduler.db
# пароль; если не задан, вход без пароля
TODO_PASSWORD=12345
```

## Тесты

1. Запустите сервер (см. выше) и не останавливайте его.
2. В другом терминале выполните из корня проекта:

bash

```bash
   go test -count=1 ./tests
```

Внимание: тест `TestTasks` удаляет все задачи из базы.

Параметры в `tests/settings.go`:

go

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true // проверка правил w и m
var Search = true       // проверка поиска
var Token = ``
```

Если сервер запущен **без** `TODO_PASSWORD`, `Token` оставьте пустым.

Если задан `TODO_PASSWORD`, тестам нужен токен:

1. Откройте [http://localhost:7540](http://localhost:7540) и войдите с этим паролем.
2. Скопируйте значение куки `token`: `F12 → Application → Cookies → localhost:7540 → token`.
3. Вставьте его в `Token` между обратными кавычками.

Токен действует 8 часов и подходит только к паролю, с которым был получен.

## Docker

Сборка образа (из корня проекта):

bash

```bash
docker build -t go-final-project .
```

Запуск контейнера. База будет храниться на хосте в папке `data/` проекта:

bash

```bash
mkdir -p data
docker run -d --name scheduler -p 7540:7540 -v "$(pwd)/data:/data" go-final-project
```

**Git Bash на Windows** подменяет пути в `-v`, поэтому там команда такая:

bash

```bash
MSYS_NO_PATHCONV=1 docker run -d --name scheduler -p 7540:7540 -v "$(pwd -W)/data:/data" go-final-project
```

**PowerShell:**

powershell

```powershell
docker run -d --name scheduler -p 7540:7540 -v "${PWD}/data:/data" go-final-project
```

Чтобы включить пароль, добавьте `-e TODO_PASSWORD=12345` перед именем образа.

Планировщик будет доступен по адресу [http://localhost:7540](http://localhost:7540). Остановить и удалить контейнер:

bash

```bash
docker stop scheduler
docker rm scheduler
```
